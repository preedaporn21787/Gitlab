## แนวทางที่พิจารณา

**ก. สูตรปิดแบบเทเวนิน + วิเคราะห์โหนดอิสระ — เลือกใช้**
ผลลัพธ์หลักมาจากวงจรสมมูลเทเวนินของตัวแบ่งแรงดัน ส่วนการตรวจสอบมาจากการ
วิเคราะห์โหนดโดยตรงด้วยค่าอุปกรณ์ดั้งเดิม สองเส้นทางการพีชคณิตที่ต่างกัน
ทั้งคู่แม่นตรง ดังนั้นถ้าไม่ตรงกันแปลว่าโค้ดผิด ใช้ได้กับทุกอินพุต เร็ว
และไม่ต้องพึ่งไลบรารีเพิ่ม

**ข. เทเวนิน + ตารางค่าอ้างอิงตายตัว** โค้ดน้อยกว่า แต่ตรวจได้แค่ไม่กี่เคสคงที่
และตรวจอินพุตที่ผู้ใช้กรอกจริงไม่ได้

**ค. เทเวนิน + สูตรประมาณ (V_B = VCC·R2/(R1+R2))** ถูกตัดออกในฐานะตัวตรวจสอบ
เพราะเป็นวงจรเดียวกันที่ละเลยภาระกระแสเบส ความไม่ตรงกันจึงเป็นเรื่องคาดหมาย
ไม่ใช่สัญญาณว่ามีบั๊ก ถ้าจะเก็บไว้ก็เป็นได้แค่หมายเหตุประกอบการสอน
ซึ่งไม่คุ้มกับขอบเขตงานที่เพิ่มขึ้น จึงไม่ทำ

## ฟิสิกส์ และสองวิธีคำนวณ

วงจร: VCC อยู่ด้านบน, R1 จาก VCC มาที่โหนดเบส, R2 จากโหนดเบสลงกราวด์,
RC จาก VCC มาที่คอลเลกเตอร์, RE จากอิมิตเตอร์ลงกราวด์ เป็น NPN
ใช้โมเดล forward active ที่ V_BE คงที่ และ β คงที่

**วิธีที่ 1 — เทเวนิน (ผลหลัก)**

```
V_BB = VCC · R2 / (R1 + R2)
R_BB = R1 · R2 / (R1 + R2)
I_B  = (V_BB − VBE) / (R_BB + (β + 1)·RE)
I_C  = β · I_B
I_E  = (β + 1) · I_B
V_B  = V_BB − I_B · R_BB
```

`V_B` คำนวณจากแรงดันตกคร่อม R_BB ในวงจรสมมูล ไม่ได้มาจาก `V_E + VBE`
เพื่อให้การเปรียบเทียบ `V_B` ระหว่างสองวิธีเป็นการตรวจสอบจริง ไม่ใช่การคิดวน

**วิธีที่ 2 — วิเคราะห์โหนดโดยตรง (ตัวตรวจสอบ)**
ใช้ KCL ที่โหนดเบส โดย I_B = (V_B − VBE) / ((β + 1)·RE):

```
V_B = [ VCC/R1 + VBE/((β+1)·RE) ] / [ 1/R1 + 1/R2 + 1/((β+1)·RE) ]
```

จากนั้น I_E = (V_B − VBE)/RE, I_B = I_E/(β+1), I_C = β·I_B

**ทั้งสองวิธีคำนวณค่าที่เหลือเหมือนกัน**

```
V_E  = I_E · RE
V_C  = VCC − I_C · RC
V_CE = V_C − V_E
```

สองวิธีสมมูลกันทางพีชคณิต แต่มาจากจุดตั้งต้นต่างกัน (แหล่งจ่ายสมมูล เทียบกับ
ความนำที่โหนด) แอปจะรายงาน
`max |ค่าหลัก − ค่าตรวจ| / max(1, |ค่าหลัก|)` จากผลลัพธ์ทั้งเจ็ดค่า
เกณฑ์ความสอดคล้อง: `1e-9` ถ้ามากกว่านี้ให้ถือว่าการตรวจสอบล้มเหลวและแสดงให้ผู้ใช้เห็น

**คัตออฟเป็นกรณีพิเศษ** ถ้า `V_BB ≤ VBE` ทรานซิสเตอร์หยุดนำ และโมเดล
forward active ใช้ไม่ได้ ทั้งสองวิธีจะถูกตัดวงจรให้คืนผลชุดเดียวกันที่ประกาศไว้
แทนการแก้สมการ: I_B = I_C = I_E = 0, V_E = 0, V_B = V_BB, V_C = VCC,
V_CE = VCC และรายงานการตรวจสอบไขว้ว่า "ไม่ใช้บังคับ" สำหรับกรณีนี้
โดยไม่อ้างเกินจริง

นี่ไม่ใช่การคิดมากเกินเหตุ ถ้าแก้สมการตรง ๆ เคส VCC 12 V, R1 47k, R2 1k,
RC 4.7k, RE 1k, β 150 จะได้ V_C = 14.09 V ซึ่งสูงกว่าไฟเลี้ยง และ V_CE = 14.53 V
โมเดล forward active ต้องถูกปฏิเสธ ไม่ใช่แค่กำกับด้วยหมายเหตุ

**การตรวจสอบไขว้มีค่าแค่ไหน** สองวิธีสมมูลกันทางพีชคณิต ค่าต่างของมันจึงเป็นศูนย์
โดยธรรมชาติเมื่อโค้ดถูก การตรวจสอบไขว้จึงกันความผิดพลาดจากการพิมพ์ผิดหรือ
การเขียนโค้ดผิดในเส้นทางใดเส้นทางหนึ่ง ไม่ใช่หลักฐานภายนอกว่าฟิสิกส์ถูก
หลักฐานภายนอกคือเคสอ้างอิงที่คำนวณมือในชุดเทสต์ และเอกสารนี้พูดตามจริง
ไม่ขายเกิน

**อิ่มตัวเป็นการเตือน ไม่ใช่การแก้สมการใหม่** เมื่อ V_CE < 0.3 V (และแน่นอนเมื่อ
V_C ≤ V_B) โมเดล β คงที่ใช้ไม่ได้ ค่า I_C ที่รายงานเป็นเพียงขอบเขตบน ไม่ใช่ค่า
ทางกายภาพ แอปต้องบอกเรื่องนี้อย่างชัดเจน

## การจำแนกเขตการทำงาน

ตรวจตามลำดับนี้

1. `V_BB ≤ VBE` → **คัตออฟ** เตือน: ทรานซิสเตอร์หยุดนำ ไม่มีกระแสคอลเลกเตอร์
2. `V_CE ≤ 0.3 V` หรือ `V_C ≤ V_B` → **อิ่มตัว** เตือน: โมเดล β คงที่ใช้ไม่ได้
   ค่า I_C เป็นเพียงขอบเขตบน
3. นอกนั้น → **แอคทีฟ** ไม่มีคำเตือน

**ตัดออกเพื่อคุมขอบเขต:** คำแนะนำเสริมอย่าง "β < 20 ภาระกระแสเบสสูง" และ
"V_CE < 1 V สวิงแคบ" ไม่ใช่เขตการทำงาน จึงไม่ทำในแล็บนี้ เหลือเพียงการจำแนก
สามเขตตามที่ระบุไว้ข้างต้น

## การตรวจสอบข้อมูลนำเข้า

ข้อผิดพลาดจะถูกรายงานเป็นข้อความรายช่อง ฟอร์มถูกแสดงใหม่พร้อมค่าที่กรอกไว้

| ช่อง | กติกา |
|---|---|
| ทุกช่อง | จำเป็น, แปลงเป็นเลขฐานสิบได้, เป็นค่าจำกัด (ไม่รับ NaN/inf) |
| VCC | > 0 |
| R1, R2, RC, RE | > 0 (RE = 0 จะหารด้วยศูนย์ในการวิเคราะห์โหนด) |
| β | ≥ 1 |
| VBE | 0 ≤ VBE < VCC |

คำเตือนที่ไม่บล็อกการส่งมีเพียงข้อเดียว: VBE นอกช่วง 0.6–0.8 V (ค่าปกติของ
รอยต่อซิลิคอน) ส่วนคำเตือนเรื่อง β ต่ำ และ V_CE ต่ำ ถูกตัดออกพร้อมกับการลดขอบเขต
เพราะไม่ใช่การจำแนกเขตการทำงาน

อ่านค่าอินพุตเป็นสตริง ตัดช่องว่าง และแปลงครั้งเดียว ไม่แปลง float ในเทมเพลต
หรือใน route

  เส้นทางหนึ่งพัง ล้มเหลวอย่างส่งเสียงดัง
- เทสต์ route ตรวจตัวเลขที่เรนเดอร์ออกมา ไม่ใช่แค่ 200

## วิธีพิสูจน์ว่า backend คำนวณเองจริง

ข้อกำหนดนี้ตรวจได้ด้วยหลักฐานสี่ชั้น ซึ่งตรวจเองได้ก่อนอนุมัติและหลังสร้างเสร็จ

**1. หลักฐานเชิงโครงสร้าง (อ่านโค้ด)**

- `bjt_bias/engineering.py` มีแต่สูตรจากหัวข้อ "ฟิสิกส์ และสองวิธีคำนวณ"
  ไม่มี dict หรือ list ของคำตอบสำเร็จรูป และไม่มี `if` ที่แมปอินพุตไปยังผลลัพธ์
- `app.py` ทำหน้าที่แปลงฟอร์ม เรียกฟังก์ชันใน `engineering.py` แล้วส่งผลเข้าเทมเพลต
  ไม่มีเลขคงที่ของผลลัพธ์
- `templates/index.html` ไม่มีแท็ก `<script>` เลย การคำนวณจึงเกิดฝั่งเซิร์ฟเวอร์เท่านั้น

**2. หลักฐานเชิงตัวเลข (ค้นหาคำตอบที่ฝังไว้)**

ค่าอ้างอิง `1.323675` และ `4.446227` ต้องปรากฏเฉพาะใน `tests/` เท่านั้น
ถ้าพบใน `engineering.py` หรือ `templates/` แปลว่ามีการฝังคำตอบ

**3. หลักฐานเชิงพฤติกรรม (ผลต้องเปลี่ยนตามอินพุต)**

มีเทสต์บังคับสองตัวที่กันการ hardcode ได้จริง

- `test_output_changes_with_input` — สองชุดอินพุตต่างกันต้องให้ I_C ต่างกัน
- `test_ic_scales_with_vcc` — เพิ่ม VCC แล้ว I_C ต้องเพิ่มขึ้นตามทิศทางที่ถูกต้อง

ถ้ามีการฝังคำตอบ เทสต์พวกนี้จะไม่ผ่าน

**4. หลักฐานจากการรันจริง**

```
python -m pytest -q
python app.py
```

แล้วกรอกสองชุดค่าที่ต่างกัน (เช่นเปลี่ยน R2 จาก 10k เป็น 22k) ผลบนหน้าจอต้องเปลี่ยน
ตามสมการ ไม่ใช่คงที่

**คำสั่งตรวจเร็วสำหรับผู้อนุมัติ**

```powershell
Select-String -Path templates\index.html -Pattern "<script"
Select-String -Path bjt_bias\engineering.py -Pattern "1\.323675|4\.446227"
Select-String -Path app.py -Pattern "1\.323675|4\.446227"
```

ทั้งสามคำสั่งต้องไม่พบผลลัพธ์

## สิ่งที่เหลือให้ผู้สร้างตัดสินใจ

- ค่า CSS ที่แน่นอน และถ้อยคำบนหน้าที่นอกเหนือจากป้ายที่ระบุไว้
- ชื่อฟังก์ชันช่วยภายใน และลำดับฟิลด์ของ dataclass

## การตัดสินใจที่ทำไว้ในเอกสารนี้

- เลือกแนวทาง ก สำหรับการตรวจสอบไขว้
- UI ภาษาไทย สัญลักษณ์อังกฤษ
- ซ่อมเศษ merge ที่ค้างสองไฟล์ใน commit นี้
- ใช้ `.venv` + `requirements.txt` แทนการติดตั้งลงระบบ
- คัตออฟตัดวงจรทั้งสองตัวแก้สมการ แทนการรายงาน V_BE ติดลบ
- อิ่มตัวรายงานเป็นการเตือนบนโมเดลที่ใช้ไม่ได้ ไม่แก้สมการใหม่
- ตัดขอบเขตกลับมาเหลือ DC bias: ไม่มีคำแนะนำเสริม, เทมเพลตไฟล์เดียว,
  ไม่มีสคริปต์ช่วยรัน
- `V_B` ของวิธีที่ 1 มาจาก `V_BB − I_B·R_BB` เพื่อให้การตรวจสอบไม่คิดวน
- README คงข้อความเดิมทั้งสองชุดไว้และเพิ่มหัวข้อ BJT แทนการลบ
