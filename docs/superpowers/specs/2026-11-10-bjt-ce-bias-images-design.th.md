# เอกสารออกแบบ: แผนภาพวงจรและเส้นโหลดไลน์ (ส่วนเสริม)

วันที่: 2026-11-10
สถานะ: รออนุมัติ
ขนาดงาน: การเปลี่ยนแปลงเล็ก (small change)
ต่อยอดจาก: `2026-11-10-bjt-ce-bias-design.th.md`

## เจตนา (Intent)

หน้าเว็บปัจจุบันแสดงเฉพาะตัวเลข ผู้ใช้ต้องจินตนาการเองว่าวงจรหน้าตาอย่างไร
และจุดทำงานอยู่ตรงไหนเมื่อเทียบกับขีดจำกัดของวงจร

เพิ่มภาพสองชิ้นเพื่อให้หน้าเว็บอธิบายตัวเองได้ และใช้ประกอบรายงานแลปได้:

1. **แผนภาพวงจร** ไบแอสแบบแบ่งแรงดัน พร้อมป้ายโหนด V_B / V_C / V_E
2. **กราฟเส้นโหลดไลน์** I_C–V_CE พร้อมจุด Q ที่คำนวณจากค่าที่ผู้ใช้กรอกจริง

## เป้าหมาย (Goals)

- แผนภาพวงจรวางเหนือฟอร์มกรอกข้อมูล เห็นได้ตั้งแต่เปิดหน้า
- กราฟเส้นโหลดไลน์แสดงในส่วนผลลัพธ์ คำนวณสดจากอินพุตจริง
- ทั้งสองภาพเป็น SVG: คมทุกขนาดซูม พิมพ์ลงรายงานได้ ไม่แตก
- ไม่เพิ่ม dependency ใหม่ และไม่ใช้ JavaScript
- แผนภาพวงจรเป็นไฟล์แยก ดาวน์โหลดไปแปะในรายงานได้โดยตรง

## สิ่งที่ไม่ทำ (Non-goals)

- ไม่มี AC / transient / กราฟตอบสนองความถี่
- ไม่มี interactive zoom, pan, หรือ hover tooltip
- ไม่มีปุ่ม export / ดาวน์โหลดจากหน้าเว็บ
- ไม่แสดงค่าแรงดันจริงบนแผนภาพวงจร (ตัวเลขอยู่ในตารางผลลัพธ์แล้ว)
- ไม่วาดแผนภาพแทนวงจรจริง (schematic editor)

## สิ่งที่ถือว่าล้มเหลว (Anti-goals)

- จุด Q ที่วาดไม่อยู่บนเส้นโหลดไลน์
- แผนภาพที่ป้ายโหนดผิดตำแหน่งหรือผิดชื่อ
- ภาพที่แสดงค่าคงที่ตายตัว ไม่เปลี่ยนตามอินพุต
- กราฟที่ทำให้หน้าเว็บพังในเขตคัตออฟหรืออิ่มตัว

## แนวทางที่พิจารณา (Approaches)

### 1. SVG สร้างฝั่งเซิร์ฟเวอร์ด้วย Python + ไฟล์ SVG นิ่ง — **เลือกใช้**

`bjt_bias/plotting.py` เป็นฟังก์ชันบริสุทธิ์ที่คืนสตริง `<svg>` ทั้งก้อน
ส่วนแผนภาพวงจรเป็นไฟล์ `static/circuit.svg` ที่เขียนมือ

- ข้อดี: ไม่เพิ่ม dependency, ไม่ใช้ JS, สีตรงกับ CSS ที่มีอยู่, ทดสอบได้ด้วยการ parse XML
- ข้อเสีย: ต้องเขียนพิกัด SVG เอง และแก้ไขด้วยมือเมื่อเปลี่ยนเลย์เอาต์

### 2. Chart.js วาดฝั่งเบราว์เซอร์ — **ตัดออก**

- ตัดเพราะ: มีเทสต์ `test_template_has_no_script_tag` ที่ล็อกไว้ว่าเทมเพลตห้ามมี `<script>`
  และสเปกเดิมระบุ "ไม่มี JavaScript" เป็น anti-goal การเพิ่ม JS จะทำให้เทสต์แดง
  และต้องแก้ invariant ที่ตั้งใจไว้แต่แรก อีกทั้งต้องพึ่ง CDN

### 3. Matplotlib สร้าง PNG — **ตัดออก**

- ตัดเพราะ: เพิ่ม dependency ใหม่, เป็นภาพ raster ที่แตกเมื่อพิมพ์หรือซูม,
  ตั้งสีให้ตรงกับ CSS ได้ยาก และสร้างไฟล์ชั่วคราวที่ต้องจัดการ lifecycle

## การออกแบบ (Design)

### แผนภาพวงจร — `static/circuit.svg`

- ไฟล์ SVG เดี่ยว มี `viewBox` จึงปรับขนาดได้ตามหน้าจอ
- แสดง: ราง VCC ด้านบน, R1 ต่อลงมาที่โหนดเบส, R2 ต่อลงกราวด์, RC ไปคอลเลกเตอร์,
  RE ไปอิมิตเตอร์, สัญลักษณ์ NPN, จุดต่อที่โหนด V_B / V_C / V_E พร้อมป้ายชื่อ
- ลูกศรกระแส I_B (เข้าเบส), I_C (ลงคอลเลกเตอร์), I_E (ออกอิมิตเตอร์)
- สีใช้ชุดเดียวกับ `static/style.css` (เส้น `--line`, ตัวอักษร `--ink`, ป้าย `--muted`)
- เรียกใช้ด้วย `<img src="{{ url_for('static', filename='circuit.svg') }}">`
  อยู่ใน `<figure>` พร้อม `<figcaption>`

### กราฟเส้นโหลดไลน์ — `bjt_bias/plotting.py`

ฟังก์ชันเดียว: `load_line_svg(inputs: BiasInputs, op: OperatingPoint) -> str`

- แกน X: V_CE (V) ช่วง 0 ถึง VCC
- แกน Y: I_C (mA) ช่วง 0 ถึง `VCC / (RC + RE) * 1000`
- เส้นโหลดไลน์: จากจุดตัดแกน Y `(0, VCC/(RC+RE))` ไปจุดตัดแกน X `(VCC, 0)`
  ตามสมการ `V_CE = VCC − I_C·(RC + RE)`
- จุด Q: วงกลมทึบที่ `(V_CE, I_C)` ของผลลัพธ์ พร้อมป้ายค่า
- ถ้าจุด Q อยู่นอกช่วงแกน (เช่น เขตอิ่มตัวที่ V_CE ติดลบ) ให้ตรึงเครื่องหมายไว้ที่ขอบกราฟ
  และกำกับว่า "นอกช่วง" แทนการปล่อยให้หลุดออกนอกเฟรม
- คืน `<svg>` ที่มี `role="img"` และ `<title>` สำหรับโปรแกรมอ่านหน้าจอ
- ฟังก์ชันบริสุทธิ์: ไม่แตะไฟล์ ไม่มีสถานะภายนอก

### ชั้นเว็บ — `app.py`

- เมื่อมีผลลัพธ์ ส่ง `chart_svg=load_line_svg(result.inputs, result.primary)` เข้าเทมเพลต
- เทมเพลตเรนเดอร์ด้วย `{{ chart_svg|safe }}`
- เหตุผลที่ `|safe` ปลอดภัย: สตริง SVG ประกอบจากตัวเลขที่ฟอร์แมตด้วยโค้ดเราเอง
  ทั้งหมด ไม่มีข้อความจากผู้ใช้ถูกแทรก จึงไม่มีช่องทาง XSS

### เทมเพลต — `templates/index.html`

- `<figure>` แผนภาพวงจร วางเหนือ `<form>`
- `<figure>` กราฟ วางใน `<section class="result">` ใต้ตารางตัวเลข
- ไม่มี `<script>` เพิ่ม (คง invariant เดิม)

### เทสต์ — `tests/test_plotting.py` (ใหม่) และ `tests/test_app.py` (เพิ่ม)

`test_plotting.py`:
- ผลลัพธ์ parse เป็น XML ได้ (ใช้ `xml.etree.ElementTree`)
- จุดตัดแกนตรงกับสูตร `VCC/(RC+RE)` และ `VCC`
- พิกัดจุด Q ตรงกับ `op.vce_v` / `op.ic_a`
- เขตคัตออฟ: ไม่ crash และจุด Q อยู่ที่ `(VCC, 0)`
- เขตอิ่มตัว: ไม่ crash, มีข้อความ "นอกช่วง", และเครื่องหมายถูกตรึงในเฟรม
- ไม่มี `<script>` ในสตริงที่สร้าง
- เปลี่ยน VCC แล้วสเกลแกนเปลี่ยนตาม

`test_app.py` (เพิ่ม):
- GET: มี `<img>` ของ `circuit.svg`
- POST ค่าถูกต้อง: มี `<svg` ของกราฟ และมีข้อความ I_C ในกราฟ
- POST ค่าไม่ถูกต้อง: ไม่มีกราฟ

## ความเสี่ยงและวิธีรับมือ

| ความเสี่ยง | วิธีรับมือ |
|---|---|
| จุด Q นอกช่วงแกนในเขตอิ่มตัว | ตรึงที่ขอบกราฟ + กำกับ "นอกช่วง" และมีเทสต์ล็อก |
| `|safe` เปิดช่อง XSS | SVG ประกอบจากตัวเลขที่เราฟอร์แมตเอง ไม่มีข้อความผู้ใช้ — มีเทสต์ยืนยันว่าไม่มี `<script>` |
| พิกัด SVG ผิดเมื่อ VCC เปลี่ยน | คำนวณพิกัดจากสเกลที่ derives จาก VCC ทุกครั้ง ไม่ใช้ค่าคงที่ |

## สิ่งที่เหลือให้ผู้สร้างตัดสินใจ

- ความละเอียดของเส้นกริดและจำนวน tick บนแกน
- ตำแหน่งป้ายชื่อกำกับบนแผนภาพวงจร
- การเว้นระยะ (margin) ภายใน `<figure>`
